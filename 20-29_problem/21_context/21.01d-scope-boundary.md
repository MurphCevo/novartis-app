## In Scope (Phase 1  - PoC)

### Agents

| # | Use Case | What We Build |
|---|---|---|
| UC-4 | Knowledge Discovery | Semantic search across approved assets, strategy docs, and campaign performance data. Intent-based retrieval regardless of phrasing. |
| UC-5 | Content Generation | AI-drafted compliant copy and creative variants from approved templates, content blocks, and audience context. |
| UC-10 | Asset Tagging | Automatic metadata tagging based on content type, therapy area, audience, key message, and usage context. |

### Interface

- Autopilot Assistant  - a single natural-language chat interface through which marketers interact with all agents.

### Integration Targets

- Veeva Vault PromoMats (VVPM)
- Aprimo / Fuse
- SharePoint (post-G Drive migration)
- Sherlock (strategy & journey docs)
- Customer Data Hub / Snowflake
- Salesforce Marketing Cloud
- Google Analytics 4
- Veeva Oncore CRM
- ShamanGo / Anthill Activator (modular templates)

### Cross-Cutting Concerns

- LLM observability and evaluation metrics
- CI/CD pipelines for agent deployment
- Role-based access control
- Query and result logging (auditability)
- Data security  - no training on Novartis data

## Out of Scope

| Item | Reason |
|---|---|
| Full Autopilot Workbench (web app) | Phase 2/3. PoC validates agents first. |
| Video generation (UC-6) | Low readiness. Depends on tooling that doesn't exist yet. |
| Creative personalisation (UC-7) | Low readiness. Requires maturity in segmentation and content modularity. |
| CX journey automation (UC-11) | Medium readiness. Deferred until agent layer is proven. |
| Performance optimisation (UC-12) | Medium readiness. Requires data integration maturity. |
| Workflow orchestration (UC-13) | Medium readiness. Logical Phase 2 extension. |
| Data cleansing or migration | Client responsibility. We consume clean APIs. |
| Building APIs for source systems | Novartis product owners provide these. We integrate to them. |
| Replacing existing tools | We connect alongside, not in place of. |
| Training the base LLM on Novartis data | Prohibited by governance policy. Fine-tuning on approved copy is in scope; base model training is not. |

---

## The Grey Zone

These items are not committed but may surface during the PoC. If they arise, they need an explicit decision.

| Item | Trigger | Decision Path |
|---|---|---|
| Additional use cases pulled forward | Client requests during PoC | Evaluate readiness + capacity. Document in `33_decisions/`. |
| Source system data not API-ready | Technical discovery reveals gaps | Surface immediately. Client resolves. May impact timeline. |
| Compliance review process changes | Shift-left compliance reveals process friction | Recommend but don't own process redesign. |
| Multi-market expansion | Success in AU market creates demand | Out of PoC scope. Factor into scale-up roadmap. |
| Integration with tools under replacement | Platform transitions overlap with PoC timeline | Align with client on target-state vs current-state integration. |

---

## Scope Test

Before adding anything to the PoC, ask:

1. Is it one of the three committed use cases (UC-4, UC-5, UC-10)?
2. Does it serve the Autopilot Assistant interface?
3. Can it be validated within the PoC timeline (Apr -Aug 2026)?
4. Does the data source have a usable API today?

If any answer is no, it belongs in Phase 2+ or needs an explicit scope change decision.
